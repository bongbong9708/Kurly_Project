# 05. 검색어가 비어 있을 때 최근 검색어 표시 (Issue #3·#4, PR #21)

## 목표

검색을 실행하면 최근 검색어로 저장하고, 입력이 비어 있으면 최근 검색어를 최대 10개 보여준다.
중복(대소문자 무시) 갱신, 최신순 정렬, 10개 제한 정책을 UseCase에 둔다.

## AI 응답 요약

- 설계 선택지 3개 제시, 각각 추천안 표시
  1. UseCase 형태: `RecentSearchUseCase` 하나에 `fetch`/`save` (추천) vs 동작별 UseCase
  2. 중복일 때 표기: 새로 입력한 표기로 교체 (추천) vs 처음 표기 유지
  3. 정렬: 저장 시 정렬, `fetch`는 그대로 (추천) vs `fetch`에서도 정렬
- 가정 명시: 검색이 실패해도 최근 검색어는 저장한다
- `RecentSearchUseCase`
  - 테스트 6개 먼저 작성 → 컴파일 실패 확인 → 구현
  - 중복은 "삭제 후 추가"로 처리해 개수가 늘지 않으므로 10개 제한에 걸리지 않음
  - 현재 시각을 `now: () -> Date`로 주입
  - trim은 ViewModel에서 하고 UseCase는 trim된 값을 받는다고 주석에 명시
  - 정책 코드를 하나씩 지워 테스트가 잡는지 확인: 중복 제거 삭제 → 대소문자 테스트 실패, 10개 제한 삭제 → 11번째 테스트 실패
  - "10개가 찬 상태에서 중복 저장" 테스트는 중복 제거를 지워도 통과함 (단독으로는 그 버그를 못 잡음)
- `SearchViewModel`: 검색 실행 시 저장, `recentSearches` 갱신. ViewModel 테스트 3개 추가
- `SearchView`: 입력이 비어 있으면 검색 상태와 상관없이 "최근 검색" 목록 표시
- **테스트 중 크래시 발견 (#2부터 있던 잠재 버그)**
  - 전체 테스트가 10분 넘게 끝나지 않음 → 테스트별 시간 제한을 걸어 원인 테스트를 좁힘
  - ViewModel을 만들고 바로 버리는 테스트에서 `SearchViewModel` 해제 시 SIGABRT
    (`swift_task_deinitOnExecutorMainActorBackDeploy`)
  - iOS 18.6에서만 크래시, iOS 27.1에서는 통과. `nonisolated deinit {}` 추가 시 iOS 18.6에서도 통과
  - 원인 추정(검증 안 함): 빌드 설정 `SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor` +
    `SWIFT_APPROACHABLE_CONCURRENCY = YES`로 deinit이 메인 액터에서 실행되고, 그 호환 코드가 iOS 18 런타임에서 깨짐
  - 선택지 제시: A `nonisolated deinit` / B 빌드 설정 변경 (B는 효과 미검증)
- #4(날짜 내림차순 정렬)의 완료 기준 "재검색하면 맨 위로 온다"가 UseCase 테스트에 이미 포함되어,
  이번 PR에서 #4도 함께 닫을지 질문 → PR 본문에 `Closes #4`와 근거 테스트를 추가
- 빌드 설정의 기본 액터 격리가 MainActor라 CLAUDE.md의 "Swift 5 모드, strict concurrency 미적용" 전제와 실제가 다르다는 점을 알림 (수정하지 않음)
