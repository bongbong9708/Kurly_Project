- 코드 작성 전 접근 방식과 선택지 4개 제시, 각각 추천안 표시
  1. 검색바: `.searchable` (추천) vs 커스텀 `TextField`
  2. 상태 모델: `enum State` (추천) vs 프로퍼티 여러 개
  3. #2와 #8 경계: 최소 `List`(name만) (추천) vs 개수 텍스트만
  4. `+` 인코딩: #2에서 수정 (추천) vs 별도 이슈
- 가정 명시: trim 후 빈 문자열이면 무시 / 재검색 시 이전 Task 취소 / App에서 Repository 직접 생성 주입
- `+` 인코딩
  - 실패하는 테스트(`c++` → `q=c%2B%2B`)를 먼저 작성해 실패 확인
  - `percentEncodedQuery`에서 남은 `+`를 `%2B`로 치환
- `SearchViewModel` (`@Observable`, `@MainActor`)
  - 테스트 7개 먼저 작성 → 컴파일 실패 확인 → 구현
  - 재검색 시 이전 `Task` 취소, 결과 반영 전에 `Task.isCancelled` 확인
  - 이 guard를 지우면 재검색 테스트 2개가 실패하는 것을 확인 (테스트가 실제로 버그를 잡는지 검증)

- `SearchView`: `NavigationStack` + `.searchable` + `.onSubmit(of: .search)`, 상태별 최소 화면
- 템플릿 잔여물 삭제: `ContentView.swift`, `KurlyProjectTests.swift`
