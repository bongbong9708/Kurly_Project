## AI 응답 요약

- 이슈 순서 제안: #3은 화면에 최근 검색어를 보여주려면 실제 저장소가 필요하므로 #6을 먼저 하자고 제안
- 설계 선택지 4개 제시, 각각 추천안 표시
  1. Repository 범위: 목록 전체 `fetch`/`save`만 (추천) vs `add`/`delete`/`deleteAll`
  2. 동기 (추천) vs `async`
  3. Codable 위치: Data 레이어에서 `extension RecentSearch: Codable` (추천) vs `RecentSearchDTO` 분리
  4. 디코딩 실패 시 빈 목록 (추천) vs 에러 던지기
- 테스트 4개 먼저 작성 → 컴파일 실패 확인 → 구현
- **3번 추천안이 컴파일되지 않음**
  - Swift는 Codable 자동 구현(synthesis)을 타입을 선언한 파일 안의 extension에서만 해준다
  - 확인하지 않은 가정을 추천안으로 제시했음. 빌드 에러로 발견하고 멈춘 뒤 선택지를 다시 제시
    (Entity에 직접 채택 / DTO 분리 / extension에서 수동 구현)
- `RecentSearchDTO`(Codable) + `init(_ entity:)` / `toDomain()` 변환
- `save`의 인코딩은 `try!` 사용. String과 Date만 담겨 실패할 수 없다고 보고 주석으로 근거를 남김
- 테스트에서 깨진 데이터를 넣기 위해 `storageKey`를 `internal static`으로 노출
