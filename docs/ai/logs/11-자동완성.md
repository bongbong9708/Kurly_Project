## AI 응답 요약

- 설계 선택지 A~F 제시, 추천안 표시
  - A. 자동완성 위치: 직접 만든 List (추천) vs `.searchSuggestions`
  - B. 입력 중 판단: 마지막 검색어(`lastKeyword`)와 비교 (추천) vs `isEditing` 상태
  - C. 필터링 위치: `RecentSearchUseCase`가 목록을 넘겨받아 거름 (추천) vs ViewModel 계산 프로퍼티
  - D. 일치 없음: 빈 목록 (추천) vs 안내 문구
  - E. 행 탭: 바로 검색 (추천) vs 글자만 채움
  - F. 날짜: 형식 고정 (추천) vs 시스템 형식
- 답변을 받은 뒤 남은 해석 3가지를 다시 질문
  - "결과가 있을 때만"을 그대로 따르면 로딩·에러·결과 없음 화면이 사라진다 → 상태별 화면 유지로 결정
  - 입력 중 일치 없음 → 빈 목록으로 결정
  - `lastKeyword`를 없애면 #12의 "고친 글자가 아니라 실패한 검색어로 다시 시도" 경우가 생기지 않는다 → 테스트 교체로 결정
- 1차 구현: ViewModel에 `isEditing`(`query`의 `didSet`에서 `true`, `search()`에서 `false`)
  - **값이 같을 때 무시하는 조건(`query != oldValue`)은 논의 없이 AI가 넣음** (2차에서 삭제됨)
- `isSearchPresented` 기준으로 바꾸라는 요청에 바로 바꾸지 않고 시뮬레이터로 먼저 확인
  - 키보드 search 후에도 검색바가 활성(Cancel 표시) → 그대로 쓰면 결과가 보이지 않는다고 반박
  - SwiftUI `TextField`에는 `isEditing`이 없고(UIKit 속성), `.searchable` 포커스(`.searchFocused`)는 iOS 18+라고 설명
  - 선택지 3가지: 1) ViewModel `isEditing` 유지 (추천) 2) View `@State` 3) `isSearchPresented` + 검색 시 `false`로 검색바 닫기 → 3 선택
- 3번 구현 후 시뮬레이터 확인
  - 열려 있던 검색바를 닫으면 검색어는 남아 있지만 닫힌 검색바에 placeholder만 보임 (다시 누르면 검색어가 보임)
  - 닫힌 상태에서 최근 검색어를 누르면 검색바에 검색어가 보임
- 목록 중복 질문에 대한 답
  - 두 목록을 가르는 조건은 `isSearchPresented`가 아니라 `query.isEmpty` (검색바를 열고 아무것도 안 쓴 상태는 최근 검색어여야 함)
  - A. 겹치는 검색어 버튼만 함수로 빼기 (추천) vs B. 한 목록에 조건 4곳 → A 선택
  - A로 구현한 뒤, 두 데이터가 같은 `[RecentSearch]`이니 목록 하나로 합치라는 요청 → 목록 하나로 합치고 A에서 뺀 `searchButton`은 다시 인라인
- 중간 결과 (`isSearchPresented` 방식. 이후 ViewModel `isEditing` → 키보드 알림 방식으로 두 번 더 바뀜)
  - UseCase: `suggestions(for:in:)`. 입력을 trim하고 `.caseInsensitive`로 포함 여부를 본다. 받은 순서(최신순) 유지
  - ViewModel: `isEditing`·`lastKeyword` 삭제. `retry()`는 현재 `query`를 trim해서 다시 요청. `suggestions` 계산 프로퍼티
  - View: 입력 비어 있음 → 최근 검색어(없으면 "최근 검색어 없음") / 검색바 열림 → 자동완성 / 그 외 → 검색 상태별 화면
  - 키보드 search, 최근 검색어 탭, 자동완성 탭 모두 `isSearchPresented = false` 후 검색
  - `recentSearchList` 하나에서 `query.isEmpty`로 분기: 데이터(`recentSearches` / `suggestions`), 행 오른쪽(x / 날짜), 헤더·전체삭제 유무
  - 자동완성 행: 헤더·전체삭제·x 없음, 오른쪽에 `yy. MM. dd.` 날짜
  - 최근 검색어가 없으면 안내 화면을 보여주게 되어 "전체삭제"의 `if !recentSearches.isEmpty` 조건을 AI가 지움
- 공백만 입력한 경우 자동완성은 빈 목록이 된다 (따로 처리하지 않음)
- 수정 요청 1: 검색 후 검색바가 비어 보이는 문제
  - 임시 로그로 확인: 검색바를 닫을 때 `query` 바인딩은 바뀌지 않는다 (`presented=false query=go`). 검색바 표시만 비워진다
  - 시도 1: 닫힌 뒤 다음 런루프에 같은 값을 다시 넣음 → 해결 안 됨
  - 시도 2: 다른 값(`query + " "`)을 넣었다가 원래 값으로 되돌림 → 해결 안 됨
  - 닫는 애니메이션이 끝난 뒤 비워지는 것으로 추정 (미확인). 지연 시간에 기대는 수정이 되므로 멈추고 사용자에게 선택을 넘김. 실험 코드는 모두 제거
- 수정 요청 2: 자동완성에 일치하는 항목이 없으면 "일치하는 최근 검색어 없음" 안내 화면 (D1 빈 목록에서 변경)
  - 안내 문구("키보드의 검색 버튼을 누르면 저장소를 검색합니다.")는 AI가 정함
  - 목록을 그리기 전에 `content`에서 데이터가 비었는지 보고 안내 화면을 고르도록 `recentSearchList`를 `(searches, isSuggestion)`을 받는 함수로 바꿈
- 포커스 관련 질문에 대한 답
  - `.searchFocused`는 iOS 18+라 최소 iOS 17에서 쓸 수 없다. 쓰려면 최소 버전을 올리거나 `#available`로 iOS 17용 방식을 따로 둬야 한다
  - 검색어가 비어 보이는 건 포커스가 빠질 때가 아니라 검색바가 닫힐 때다. 검색바를 닫지 않으면 키보드가 내려가도 검색어가 남는다 (이 브랜치 초기 구현에서 확인)
  - `@FocusState`는 iOS 15+지만 `.searchable` 검색바에 연결하는 방법이 `.searchFocused`뿐이다. 직접 만든 `TextField`라면 `.focused`로 쓸 수 있다 (`.searchable`에 `.focused`를 다는 경우는 실행해 보지 않음)
  - 검색바를 닫지 않고 입력 중 상태를 직접 드는 방식(3번)을 추천
- 최종 변경: `isSearchPresented` 제거, ViewModel `isEditing` 복원 (1차 구현과 같은 `didSet` 방식)
  - 최근 검색어를 눌렀을 때 검색바를 활성화하던 코드도 함께 사라져 "취소" 버튼이 보이지 않게 됨 (CLAUDE.md 확정 결정과 다름)
- 키보드 알림으로 `isEditing`을 바꾸자는 제안에 대한 답 (코드 전에 문제 제기)
  - 행을 눌러도 키보드가 남아 있어 결과 대신 자동완성이 계속 보인다 → 행 탭 때 키보드를 내려야 한다
  - 하드웨어 키보드 연결 시 알림이 안 올 수 있고, WebView 입력칸 키보드도 같은 알림을 보낸다 (추정, 미확인)
  - 입력 중 판단을 단위 테스트로 확인할 수 없게 된다
- `UIApplication.shared.endEditing()`은 UIKit 기본 메서드가 아니라고 정정하고, `resignFirstResponder`를 보내는 확장을 추가하기로 함
- 추가 질문 3가지에 대한 결정
  - 검색하지 않고 키보드만 내리면 검색바 글자와 결과가 어긋남(검색 전이면 빈 화면, 이전 검색어 결과) → 그대로 둠
  - 스크롤 시 키보드 내림 → `.scrollDismissesKeyboard(.immediately)`
  - `isEditing` 위치 → View `@State`
- 구현
  - `UIApplication+EndEditing.swift` 추가
  - View: `@State isEditing`을 `keyboardWillShow`/`keyboardWillHide` 알림으로 바꿈. 행 탭 시 `endEditing()` 후 검색
  - ViewModel: `isEditing`·`didSet` 삭제. `retry()` 주석을 "검색바에 있는 검색어로 요청한다. 고친 뒤 키보드만 내리면 실패한 검색어와 다를 수 있다"로 수정
  - 테스트: 입력 중 테스트 4개 삭제
- 빈 곳 탭으로 키보드 내리기에서 문제 발생
  - 1차: 화면 전체에 `simultaneousGesture(TapGesture)` → 자동완성 행을 눌러도 검색되지 않고 빈 화면이 됨 (키보드가 먼저 내려가 목록이 사라짐)
  - 2차: `onTapGesture`로 변경 → 같은 문제
  - 제스처를 뺀 상태에서 행 탭이 되는 것을 확인해 원인을 제스처로 좁힘
  - 최종: 행이 없는 빈 화면(안내 화면 2개)에만 탭 제스처를 붙임. 목록 아래 빈 공간을 눌러서는 키보드가 내려가지 않음 (스크롤로는 내려감)
- 취소 시 idle
  - "취소"를 누르면 검색어가 비는 것을 신호로 삼아, ViewModel `query`의 `didSet`에서 비게 되면 진행 중인 요청을 취소하고 `state = .idle`로 바꿈 (AI가 정한 방식. 검색바의 지우기 버튼도 같이 idle이 됨)
  - `content` 분기: `query.isEmpty || isEditing` → `state == .idle || isEditing`
  - 결과로 검색 전 입력 후 키보드만 내리면 빈 화면 대신 자동완성(또는 일치 없음 안내)이 남음
  - `searchResultContent`의 `.idle` 분기는 도달하지 않지만 switch를 채우려고 남기고 주석을 닮
- Util 폴더
  - 옮길 파일과 폴더 위치를 질문. `Domain/SearchError.swift`는 도메인 에러라 Domain에 두자고 제안, 위치는 `Presentation/Util`을 추천
  - 결정: 확장 두 개(`SearchError+Message.swift`, `UIApplication+EndEditing.swift`)만 최상위 `Util/`로 이동
  - `SearchError+Message.swift`의 "Presentation에 둔다" 주석을 위치와 무관한 설명으로 수정

### AI의 문제

- 첫 제안(A1)은 자동완성을 최근 검색어 목록과 별개 화면으로 그렸다. 사용자가 최근 검색어 화면을 보여주는 방향으로 정정
- 두 번째 질문을 영어로 했다. 사용자가 한글로 다시 질문하라고 지적
- 사용자가 원한 것(텍스트 필드의 편집 상태)과 다르게 ViewModel에 상태를 만들었다
